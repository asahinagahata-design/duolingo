# NES DET Coach（試作版）

Nippon English School 向けの Duolingo English Test（DET）学習サポートWebアプリです。1つの画面で次のことができます。
**学習プランの作成 ／ 進捗の記録 ／ 演習問題の生成**（生徒用と講師用の画面あり）

- ビルド不要の静的サイトです（HTML・CSS・JavaScriptのみ）。外部のライブラリやCDNは使っていません
- データはブラウザの localStorage に保存され、JSONで書き出し・読み込みができます
- 初期状態ではデモ用の架空の生徒が登録されています。講師モードから実際の生徒を登録してください

## ⚠️ セキュリティに関する注意

このアプリは**学習用・デモ用**として設計されています。

- **講師PINは簡易的なロックで、セキュリティ対策ではありません**（JavaScriptのコードを見れば分かります）
- **データはブラウザの localStorage にのみ保存されます**。公開サイト上ではデータは端末ごとに分かれ、他の端末とは同期されません
- **公開サイトに実際の生徒の個人情報を入力しないでください**。データは暗号化されず、ブラウザに平文で保存されます
- 本番運用には、適切な認証・データベース・暗号化を備えたバックエンドが必要です

## GitHub Pages で公開する方法

このリポジトリは GitHub Pages でそのまま公開できます。

1. リポジトリの **Settings** を開く
2. 左メニューから **Pages** を選択
3. **Source** で **Deploy from a branch** を選択
4. **Branch** で **main** を選び、フォルダは **/ (root)** のまま
5. **Save** をクリック

数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` でアクセスできます。

## ローカルで起動する方法

```bash
python3 -m http.server 8765
# ブラウザで http://localhost:8765 を開く
```

`index.html` を直接開いても動きますが、読み上げ・録音・ファイル読み込みを確実に使うには、ローカルサーバー経由で開いてください。

## 使い方

| モード | 切り替え方 | できること |
|---|---|---|
| 生徒 | 右上の「生徒」 | ホーム（今日のタスク・スコア推移・次のレッスン）、プラン、記録（学習時間・単語・負担感・自己評価・模試スコア）、演習 |
| 講師 | 右上の「講師」→ PIN（初期値 **1234**。設定画面で変更できます） | 上記に加えて、生徒一覧（順調／注意／遅れ）、生徒の詳細（レッスンノート、記録へのコメント、単語チェックの番号出し、週ごとのメモ）、生徒の登録・編集、LLMの設定、初期データに戻す |

- **生徒の登録**：講師モード →「＋ 生徒を登録」。現在のスコア、目標、期間（締切または週数）、平日・休日の学習時間、苦手な形式などを入力すると、すぐにプランができます。目標が5点刻みでない場合（例：91）や、期間に対して伸び幅が大きい場合は、その場で注意が出ます
- **この端末の生徒**：生徒モードで表示する生徒は、設定 →「この端末の生徒」で選びます
- **共有**：設定 →「JSONを書き出す」で出したファイルを、相手の端末で「JSONを読み込む」。PINとAPIキーは書き出しに含まれません

## プラン作成のしくみ（`js/planner.js`）

- **ベース**：12週・3フェーズの計画テンプレートと、『DET総合対策』学習ノート。現行の13形式だけを使い、Read Aloud と Listen, Then Speak（2025年7月に廃止）は入れていません。Read and Select は1語5秒です（DET公式 Handbook・Scoring Guide 2026 で確認）
- **3フェーズ**：基礎・形式理解 → 長文・アウトプット → 実戦
  - 期間が2〜52週のどれでも、モジュールを合体させたり延長したりして収めます
  - フェーズ1の週数は手で決めることもできます
  - 苦手な形式に選んだものは、フェーズ2で先に扱い、余った週を追加で割り当てます
- **チェックポイント**：フェーズ1の最後、フェーズ2の最後、最終週の前の週に、公式の無料練習テストを入れます。間隔が5週を超えるところには追加します
  - 目安の点数は、現在の点から目標までを直線で結んで5点単位に丸めたもので、**予測ではありません**
- **本番の受験候補日**：受け方を「最後にまとめて」「月1回」「30日2回ペースで最大」から選べます
  - 30日に2回までのルールに合わせ、安全側で16日間隔にしています
- **見通しの判定**：「現実的／挑戦的／かなり厳しい」は、週あたりの伸び幅と学習時間から出す**NES内の目安**です
  - 公式の伸び幅データはないので、点数の約束はしない文言にしています
  - CEFRの帯（60〜95＝B1、100〜125＝B2）は公式の情報です
- **状態の判定**：次の2つのうち悪い方で決めます
  - 最新の模試・本番のスコアと、その週の目安との差（−5点以内＝順調、−10点以内＝注意、それより下＝遅れ）
  - 直近7日の学習時間が計画の何％か（80％以上＝順調、50％以上＝注意）

## 演習問題（`js/questions.js`・`js/bank.js`）

| 形式 | 内容 |
|---|---|
| Read and Select | 実在語と、実在しない語（`tools/make_wordbank.py` で作成し、wordfreq で辞書にないことを確認）を1語5秒で判定 |
| Fill in the Blanks | NES単語リスト（135語）の自作例文と、内蔵の文から出題 |
| Read and Complete | 内蔵のオリジナル段落から、C-test形式（1語おきに後半を消す）を自動で作成 |
| Listen and Type | ブラウザの読み上げ（Web Speech API）を使用、再生は3回まで |
| Interactive Reading | 6問構成。ハイライト問題はドラッグで選択し、一致度で部分点 |
| Interactive Listening | 返答を選ぶ問題（音声は1回のみ）と、75秒の要約 |
| Write / Speak About the Photo | 写真の代わりに場面説明を表示 |
| Interactive Writing、Writing Sample | タイマー、語数・接続語・複文・繰り返しの簡易チェック、公式の評価項目のセルフチェック |
| Read, Then Speak、Interactive Speaking、Speaking Sample | 準備と回答のタイマー。録音・再生はその場でだけでき、保存はしません |

- レベルは3段階（〜75／80〜100／105〜）で、最新のスコアから自動で選ばれます
- 生徒の興味に合う話題を優先して出題します
- 問題はすべてNESが作ったオリジナルで、公式問題や書籍からは写していません

### LLM連携（任意）

設定 →「LLM連携」で、OpenAI互換のエンドポイント・モデル名・APIキーを入れて「LLMで生成する」をオンにします。

- **LLMで作る形式**：Read and Complete、Interactive Reading、Interactive Writing、Writing Sample、Read Then Speak、Interactive Speaking、Speaking Sample
- **失敗したとき**：自動でオフライン生成に切り替わります
- **キーの扱い**：コードには書いていません。キーはその端末のブラウザにだけ保存されます
- **本番運用では**：キーをブラウザに置かず、サーバー側の中継（例：Cloudflare Workers）を通してください

## 公開方法

- **GitHub Pages**：リポジトリに置き、Settings → Pages → Branch を選ぶだけで公開できます（ビルドは不要）
- **Netlify / Cloudflare Pages**：フォルダをドラッグ＆ドロップするか、Publish directory にルートを指定します
- **注意**：今はデータが端末ごとに分かれているので、公開しても生徒と講師のデータは自動では同期されません

## 今の制限

- データは端末・ブラウザごとです。ブラウザのデータを消すと記録も消えるので、定期的にJSONを書き出してください
- PINは簡単なロックで、セキュリティ対策ではありません（コードを見れば分かります）
- 写真問題に写真は使っておらず、場面説明で代わりにしています
- 読み上げの声はOSやブラウザによって変わります
- 自動の採点は簡易チェックで、DETの公式採点ではありません
- 内蔵の問題の数は、各形式で数問〜十数問です
- 実在しない語は機械的に作ったもので、本番の偽単語ほど自然ではありません
- チェックポイントの目安や見通しの判定は、NES内のルールで決めたもので、根拠となる公式データはありません

## 次にやること（おすすめ）

1. **共有のバックエンド**（Supabase / Firebase / Cloudflare D1 など）：生徒と講師のアカウントを分け、端末をまたいで同期する。LINEログインも候補
2. **LLMの中継サーバー**：APIキーをサーバーで持ち、生成する量や内容のチェックもそこで行う。答案の添削（Writing・Speakingの文字起こしと評価）もここに追加する
3. **通知**：毎日の単語の進捗報告や、未記録の日のリマインドをLINEに送る
4. **教材の反映**：教材（文法書・DET公式単語帳・DETの教科書）が決まったら、日々のタスクとプランに入れる。単語帳の中身はアプリに保存せず、番号の範囲だけを管理する
5. **問題を増やす**：講師が問題を登録できる画面と、写真問題用の画像（自前で撮影したもの、またはライセンス済みのもの）
6. **スコアの記録を増やす**：4技能とサブスコア（Literacy・Comprehension・Conversation・Production）の推移グラフ
